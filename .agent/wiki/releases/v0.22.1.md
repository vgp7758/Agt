## 发布细节

- **攒批死锁修复（本版核心稳定性）**：`busy_parse` 旧判定 `any("✅" not in l)` 把 ❌ 行（任务被 /restart 中断——events 尾部 turn_start + 5 step 后无 turn_end，meta 已写 `status="failed"`，agent=None 躺平）也判忙 → 每次维护触发都入队、永不消费，pending 堆到 **21 条**。修复：`is_busy = bool(lines) and any(("✅" not in l) and ("❌" not in l) for l in lines)`——✅(done)/❌(failed) 都算空闲，只有真运行态才算忙；配套 `_restore_subagents` 读档时 meta `running` → 修正为 `failed`（重启物理上杀掉所有 daemon 线程，恢复条目不可能在跑，不修正则看板谎报「忙」→ 同款死锁）。**活验收（发布轮）**：预判兑现——wiki-updater_3 从 ❌ 积压 21 条 → 判空闲 → 全量读批次 → 复活消费 → ✅ 正常消化归档，攒批队列轮转清空。详见 [wiki-auto-maintenance · busy 检查](../features/wiki-auto-maintenance.md#busy-检查与攒批短路按-name-子串判定--多实例多行判定2026-08-26)。
- **Agent 专属页**：`/agents/<id>` 直接落位（URL 优先级高于 sessionStorage 残留，失效复位 `_main_` 兜底），与 `/agents` 管理页按路径形态区分互不冲突；坑修复两件——**静态资源 404**（子路径下相对路径解析成 `/agents/icons/...` 全 404，manifest 404 报 "Syntax error"，全部改根相对 `/icons`、`/manifest.json`）+ **URL 直达被弹回主视图**（`current_history` 对历史子 Agent——重启后磁盘恢复、agent=None——补磁盘加载分支，与 `switch_agent` 行为一致）。详见 [user-interaction · Agent 专属页](../features/user-interaction.md#agent-专属页-url-路由--agentsagent_id-直接落位2026-08commit-5393ee4修复-c819618)。
- **组网三层通道定稿**：工具级（任意调用带 server_id 路由，远程零 LLM 成本）+ 消息级异步（`remote_message`）+ 消息级同步（`remote_ask`）；auto server_id（本地 url → `agt-{port}`、远程 → `agt-{host}-{port}`，同 url 幂等复用、url 与 id 一对一）；`_REMOTE_ADMIN` 管理族豁免路由（server_id 是管理语义不是路由语义——cnb-agt 死循环根因）。详见 [multi-instance](../architecture/multi-instance.md#跨实例消息通信remote_message--remote_ask2026-08)。
- **fc 大刀首折 + 卫生性强制毕业**：首折至少吞超深档一半（203 边界/406 轮实测触发间隔 52→200 轮约 ×4，超深态留存同幅延长，缓存经济无损——摘要尾部追加式）；当前档 >60 轮无窗口压力也强制分批升前 30 轮（`GRADUATE_FORCE_TURNS=60`）。详见 [context-engine · fc 大刀首折](../architecture/context-engine.md#fc-大刀首折至少吞超深档一半2026-08commit-4d37e90)。
- **跨实例消息同步**：user 事件渲染到同 Agent 的其它客户端/CLI（前端 `_pendingLocalEcho` + CLI `_cli_echo` 两端对账，发送端自己不双渲染，零新增广播）——与 target 路由共同构成多客户端改造闭环。详见 [user-interaction · 多端消息同步](../features/user-interaction.md#多端消息同步--user-事件渲染到同-agent-的其它客户端cli2026-08commit-1168ea9)。
