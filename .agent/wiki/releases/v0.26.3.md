## 断链充值入口

**数据链**：provider 403（flatkey 欠费）→ `llm.last_failures` 逐跳收集（每次调用开头重置）→ 回退链耗尽 → `run()` except 捕获 → 从 last_failures 去重（按 url）提取充值 hint（错误消息内嵌链接 > preset recharge_url > register_url）→ `interrupted` 事件带 `recharge:[{provider,url,reason}]` → 前端渲染按钮组（`<a target=_blank>` 新标签打开，title 悬停显示失败原因）。

- **失败归类纪律**：只对 quota/auth 类失败生成按钮（`_classify_err`）——网络/限流/超时断链不冒无关充值按钮
- **配套行为变更**：401/403/404（鉴权/配额/模型不存在）也纳入回退链（此前直接炸轮）——flatkey 余额 403 冷却后切链上下一 provider，会话不断
- 完整实现与验证见 [气泡交互 · 中断轮充值入口按钮](../features/bubble-interaction.md#answer-中断轮充值入口按钮--回退链全失败一键打开2026-09-08用户提案)（引擎层，需 /restart）

## spec 批阅气泡收起

spec 通过并开始施工后，answer 区 spec 大卡片收起成一行摘要（`📐「标题」已通过，开始实施 · N 步 [📐 在抽屉中查看]`），把 answer 区还给施工过程与最终回答——`_specBubbleActive` 标记 + `case 'spec'` approved 事件触发 `collapseSpecBubble`；draft/rejected 不收起、抽屉批阅入口同样生效。**纯前端改动，Ctrl+F5 生效**。完整实现见 [气泡交互 · spec 批阅气泡收起](../features/bubble-interaction.md#spec-批阅气泡--通过后自动收起成摘要2026-09-08用户提案)。

## 更新方式

```bash
pip install -U agt-agent
```

- **当前 9000 进程**：充值入口链路（llm_client/agent 后端部分）需 `/restart` 生效；spec 收起是纯前端改动，重启后强刷即可
- **其它实例**：升级后 `/update-assets apply` 刷新播种资产（preset 的 recharge_url 等）

> 顺带：flatkey 余额不足的问题充值前依然会在——只是现在断链时能从气泡上直接点开钱包页，充完点「▶ 继续」从断点续跑，整个闭环不用翻日志。
