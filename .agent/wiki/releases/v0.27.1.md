## CNB HTTPS 反代 WS 修复（本版核心）

**现象**：CNB 容器启动 `agt-web`，经 `https://xxx-8000.cnb.run/` 打开 WebUI，控制台刷 `Mixed Content` + `SecurityError: Failed to construct 'WebSocket'`，点工具按钮再级联 `Cannot read properties of null (reading 'send')`——页面能看、消息发不出。

**根因**：主界面 `connectWS()` 硬编码 `ws://`，而浏览器禁止 HTTPS 页面发起不加密 WS 连接（Mixed Content 策略），连接构造当场失败。CNB 是 TLS 边缘反代（边缘终结 TLS → 转发容器内明文 ws），容器内服务无任何问题——问题纯在前端协议写死。`rag.html` / `workflow_debug.html` 早是协议自适应写法，主界面是唯一漏网。

**修复**（src/static/index.html 两处，服务端零改动）：

```javascript
// connectWS：协议自适应——边缘代理终结 TLS 后转容器内 ws
ws = new WebSocket(`${location.protocol==='https:'?'wss':'ws'}://${location.host}/ws`);

// sendToolCall：未连接防护，替代级联 TypeError
if(!ws || ws.readyState !== 1){ toast('⚠️ WebSocket 未连接（页面刷新可重连）——消息发不出去'); return; }
```

完整根因链与部署结构见 [user-interaction · WS 协议自适应](../features/user-interaction.md#ws-协议自适应cnb-https-反代-mixed-content-修复2026-09-13v0271)；排障速查已录入 [ops · 常见错误对照](../guides/ops.md#常见错误对照)。
