## 要点速记

- **组合模式**：`add_schedule('巡检', every_seconds=300, at='2026-09-18T10:00:00', message=...)`——at 为首触发相位起点；at 已过去自动对齐下一相位点（10:00 起每 5min、现在 11:43 → 首发对齐 11:45，不走「now+5min」漂移算法）；短格式 `HH:MM` 与相位语义冲突，明确报错
- **持久化**：存任务定义 + **`at_origin` 相位锚**（at 未填默认记 now——「假装第一次已在 now 触发过」），**不存 `next_fire`**——恢复时按锚点重算（与组合模式同一套相位对齐算法，重启不漂移）；顺手 `Lock→RLock`（嵌套加锁）+ `_LOG` 补定义
- **同名摘旧**：三处注册段（`add_interval` / `add_interval_at` / `add_at`）统一先 pop 旧条目再注册——同名改时间重设不再双投

## 后记：持久化一项从未生效——三 bug 修复（2026-09-18 · 二，commit e22062c）

本版「定时任务持久化」（95649e3）发布后用户实锤：meta.json 从未出现 `schedules` 键、重启后任务全丢。根因三连：①`_persist()` 直写 `session.extra_state` 被 session 落盘前的**覆盖式重建**（capture_runtime_state 收集清单整体覆盖）抹掉——收集清单里没有 schedules；②Scheduler 建于 `Agent.__init__`（早于 session load），`_restore()` 恒空跑；③存量任务从未落盘、无法恢复。

修复（e22062c）改单一真源：`Scheduler.export_state()` 进收集清单 + `_persist()` 只调 `sess.save()` + 恢复挂 `restore_runtime_state`（set_session/load 后标准恢复点）——详见 [background-scheduler · 持久化后记](../features/background-scheduler.md)。本页其余两项（组合模式 / 同名摘旧）不受影响；修复 `/restart` 后新设任务才真正跨重启存活。

## 更新方式

```bash
/restart                         # 本机（editable 安装）即生效；重启后持久化任务自动恢复
pip install -U agt-agent         # 其它实例 → 0.29.4
```

本机 `/restart` 一次即把本批（连同 v0.29.3 未生效的多实例通信 / MCP 两级化）全部装载——之后设置的定时任务（组合模式 / 每日闹钟 / interval 循环）**跨重启存活**，同名再设不再双投。
