## 子 Agent 唤醒链路根因修复（核心）

**根因**：旧版 `AgentRegistry`（`src/registry.py`）未引入，`agent.registry` 为 `None`，导致子 Agent `_bg` 线程完成后 `push_message(caller_id, answer)` 内部查 registry 返回 None → answer **从未入队** caller inbox → 主 Agent 永远收不到子 Agent 回复。

**修复**：引入 `AgentRegistry`，每个 Agent 实例创建时注册到全局 registry，`push_message` 通过 `registry.get(caller_id)` 定位目标 Agent 并将 answer 入其 inbox。主 Agent 下轮自动激活。

**验证状态**：三阶段验证——阶段一（/api/status 跨实例调用）通过；阶段二（9100 端口反复退出根因修正为旧实例占端口，非代码 bug）已处置；阶段三（stdin 通道验证通过 + 观测点日志已埋，等待首轮完成闭环）。

> 完整诊断链路与排障速查见 [多 Agent 体系](../architecture/multi-agent.md)。

## wiki 自动提交修复（2026-08，提交失败问题）

`wiki_auto_maintenance` 的 commit_wiki 提交曾因 **shell 转义 commit message 中的多行文本**而失败。修复方案：

- **commit_wiki 从 run_shell 改为 git_commit 节点**：内部用 subprocess **列表参数**传递 commit message，不再经过 shell 字符串拼接，多行/特殊字符安全
- **引入 snap_before / diff_wiki 机制**：提交前对 `.agent/wiki/` 打快照，diff 出精确变更清单，按清单 add+commit+push，无变更静默跳过
- **自动追加 Co-authored-by**：标识 wiki 由主 Agent + wiki-updater 协作维护

详见 [wiki-auto-maintenance](../features/wiki-auto-maintenance.md#提交失败问题2026-08-修复)。
