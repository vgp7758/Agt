# v0.29.6 发布记录

> 发布：2026-09-19（用户报告容器 WebUI 误报「🆕 新版本 v0.29.4 可用（当前 v0.29.5）」），发布提交 `ac6dd1d`（fix(webui): 版本检查双修），PyPI 版本 0.29.6（`src/paths.py` VERSION 0.29.5 → 0.29.6）。**版本检查双修补丁版**——修「比当前版本高的旧版本被误报为可更新」。

## 发布内容总览

| 类别 | 内容 |
|---|---|
| 🔧 **版本源按形态分流** | pip 形态查 PyPI JSON API（与 `pip install -U` 同源、无需 GitHub token）；桌面版查 GitHub Releases latest（桌面包从那里下载 zip）——此前一律查 GitHub Releases，0.29.5 只推 PyPI → GitHub latest 停在 v0.29.4 |
| 🔧 **语义版本比较 `_ver_gt`** | packaging 优先、缺失按数字段比较（1.2.10 > 1.2.9）；**绝不用 `!=` 兜底**——容器无 packaging 时旧兜底把 `"0.29.4" != "0.29.5"` 判 True |
| 🏷️ **版本 bump** | 0.29.5 → 0.29.6（src/paths.py 唯一真源） |

## 要点速记

- **现场实锤**（brick 容器）：`{"current":"0.29.5","latest":"0.29.4","update_available":true}`——两 bug 叠加：① 版本源 = GitHub Releases latest（0.29.5 未建 Release → latest 停在 v0.29.4）；② 比较兜底 `latest != current`（容器缺 packaging → `Version()` 抛异常 → except 兜底）→「当前已更高」被误报为「有新版本」
- **`_ver_gt(a, b)`**：`from packaging.version import Version` 优先；except 后按 `.` 分割取每段数字比较（1.2.10 > 1.2.9 正确）——**教训：版本比较永远不要用 `!=` 兜底**
- **版本源分流**：pip 形态查 PyPI JSON API（与升级命令同源、免 GitHub token、Release 建不建都准）；桌面版维持查 GitHub Releases（zip 从那下载）。24h 缓存 + 3s 超时 + 失败静默（update_available=null → 前端不渲染横幅）不变
- **附带收益**：版本源不再依赖 GitHub Release——发布流程少一个必做项（PyPI 一发即为真源）
- **顺带修**：start_agt.sh v3 加固——kill → SIGTERM 等 12s → SIGKILL 兜底 → 确认死透 + 端口真空闲才启动（修重启脚本探活探到旧进程误报 ready、实例一直跑旧代码）

## 验证

- 单元测试 5/5：`_ver_gt("0.29.4","0.29.5")=False`（关键——低版本不再误报）/ `_ver_gt("0.29.6","0.29.5")=True` / `_ver_gt("0.2.10","0.2.9")=True`（数字段正确）
- brick 实测：装 0.29.6 重启后 `/api/latest` → `{"current":"0.29.6","latest":"0.29.6","update_available":false}` ✅ 横幅消失

## 更新方式

```bash
pip install -U agt-agent    # → 0.29.6；容器：pip install -U --break-system-packages agt-agent
/restart                    # 本机（editable 安装）即生效
```
