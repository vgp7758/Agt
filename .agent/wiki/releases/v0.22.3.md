## 发布细节

- **per-provider 缓存经济学（commit 27fea56，用户提案）**：GLM miss≈hit **4x** vs DeepSeek **~60x**——折扣越悬殊越不该轻易破坏缓存前缀。两参数（均带 clamp）：`fold_target_ratio`（折叠目标线占窗口比 0.5~0.99，缺省 0.75；**调低 = 更早升档消化压力、少大折叠**）+ `detail_step`（组间步距衰减字数 0~200，缺省 15；**0 = 不衰减** → 渲染字节永不回缩 → 前缀缓存打满）。`session.fold_target()` 单一真相源（轮边界计划+保命阀共用）、冻结渲染 key 加 detail_step 维度、旁车记 fold_ratio。**语义定稿关键**：ratio 是「触发折叠后保留的水位」而非「触发阈值」；方向上 DeepSeek 60x 配**低** ratio 才对（升档断尾部小、折叠断头部大）——**DeepSeek 三件套 `0.5 + 0 + token_rotate:false`**，GLM 默认即可。详见 [context-engine · per-provider](../architecture/context-engine.md#per-provider-缓存经济学参数fold_target_ratio--detail_step2026-08-30commit-27fea56用户提案)。
- **DeepSeek 缓存实证收口**：5 组探针否证「system 合并可救缓存」假设——v4 后端**位置敏感**（头部/尾部 system 变化同样全断）、reasoning_content 不参与缓存键；13 轮探针链沉淀为随包工具 `tools/deepseek_cache_probe.py`（可复现）。修复面 = 动态注入 user 化（端到端 6%→99%），本版全量落地。详见 [context-engine · 缓存实证](../architecture/context-engine.md#deepseek-缓存行为实证v3-位置敏感--v4-system-规范化2026-08-两代后端)。
- **recent-file v3 终版（三裁定 + 两收口）**：注入侧——快照挂进「改它的那次工具调用」result content 尾（`_rf_latest_map` 按 call_id 命中，位置与唯一性兼得，归档轮天然不注入）；判阈侧——毕业判阈刨除 rf（`over = (prompt − rf_tok) > win`，panic 判阈不刨、按真实请求体积保命）；估算侧——`_rf_stripped` 剥离副本进 `_plan_fold` / `_history_tiered_msgs`，rf 不再推动不可逆历史压缩；源头侧——读工具（read_file/grep/find_function）移出 `_FILE_SNAP_TOOLS`（10→7），**只有写过的文件才配拥有全文跟屁虫**。四层口径收拢 `_rf_latest_map` 单源。详见 [context-engine · recent-file](../architecture/context-engine.md#recent-file-跟屁虫快照注入三版演进--rf-免疫收拢单源--源头收缩2026-08-29dd7fd81--39e7115--348adfc--983c417--22eaa04)。
- **窗口值生命周期（commit f57de5d，随本批落地）**：session 窗口是 llm client 创建时固化的副本，`/reload models` 旧版只刷 profile 不同步——现四入口同步（`/model` / `/reload models` / WebUI 保存模型配置 / `/config`）；旁车 `proj_stats.json` 记 `win`/`fold_target` 快照，改窗口后行为异常时的第一手排障证据。详见 [context-engine · 窗口值生命周期](../architecture/context-engine.md#窗口值生命周期llm-固化副本--改窗口四入口同步2026-08-29commit-f57de5d)。
- **发布流程插曲（工具选择教训）**：版本 bump 第一次用 shell 内联 `python -c "...replace(...)"` **没生效**（引号转义吃掉了 replace）→ build 出的还是 0.22.2 → twine 400（PyPI 版本已存在）。改用 **edit 工具**直接改 `src/__init__.py` 的 `__version__` 后重 build/upload 成功。结论：改文件一律走 edit 工具，不走 shell 内联字符串替换——shell 转义 vs 结构化参数的又一实例。
