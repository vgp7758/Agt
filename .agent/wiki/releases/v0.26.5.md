## release.py 版本真源改造（发布链修复）

**背景**：桌面版平铺打包改造（2026-09）后，`src/__init__.py` 里**不再有静态 `__version__ = "x.y.z"` 字面量**——改为反向 `from paths import VERSION as __version__`（版本唯一真源收 `paths.py`）。而 `release.py` 仍按老假设用正则扫 `src/__init__.py` 找版本号 → **匹配 0 处**，一键发布链直接失效。

**修复（release.py，本次改动）**：

| 项 | 旧 | 新 |
|---|---|---|
| 版本读取源 | `INIT = ROOT / "src" / "__init__.py"` | `PATHS = ROOT / "src" / "paths.py"` |
| 附加产物 | — | `VERFILE = ROOT / "packaging" / "version_file.txt"`（exe 版本资源，桌面版本地构建吃它） |
| `current_version()` | 扫 `__init__.py` 的 `__version__` | `re.search(r'VERSION\s*=\s*"([\d.]+)"', PATHS…)`，未命中 `sys.exit("❌ 在 src/paths.py 里没找到 VERSION（唯一真源）")` |
| `write_version(ver)` | 改 `__init__.py` | 改 `PATHS` 的 `VERSION`；若 `version_file.txt` 存在则 `re.subn(r"\d+\.\d+\.\d+", ver, …)` 同步（计数为 0 则跳过） |

**注意**：`release.py` 与 CI 的 `tools/ci_stamp_version.py` 现在**同源同语义**（都只改 `paths.VERSION` + `version_file.txt`）——本地发布链与云构建链的版本戳行为一致，见 [桌面版 · tools/ci_stamp_version.py](../features/desktop-mode.md#toolsci_stamp_versionpyci-版本戳)。

## `src/__init__.py` 导入顺序修复（PyPI sdist 构建坑）

**症状**：`python -m build`（sdist）时构建后端 import `src` 包 → 崩。

**根因**：文件里 `from paths import VERSION as __version__` 写在了 sys.path hack **之前**——build 后端 import `src` 时，CWD 下没有 `paths` 模块，同级目录（`src/`）还没进 `sys.path` → `ModuleNotFoundError`。

**修复后的文件（11 行，顺序敏感）**：

```python
"""Agt Agent 框架——src 包。确保包内绝对导入(import config 等)能找到同级模块。

导入顺序敏感（PyPI sdist 构建实测坑）：sys.path hack 必须在 from paths import
之前——build 后端 import src 时 CWD 下没有 paths，同级目录还没进 sys.path；
pip 安装（包名 agt_agent）与桌面平铺打包两种形态都依赖这个顺序。
"""
import sys, os
_pkg = os.path.dirname(os.path.abspath(__file__))
if _pkg not in sys.path:
    sys.path.insert(0, _pkg)
from paths import VERSION as __version__   # 版本唯一真源在 paths.py（桌面平铺打包共用）
```

**通用教训**：包内「sys.path hack + 同级模块导入」的组合，**hack 必须永远排在同级 import 之前**——本地跑得通是因为 CWD 恰好已在 sys.path（或已装过旧版），构建后端/干净环境立刻暴露。
