## 播种资产变更（×2）

1. **`wiki_auto_maintenance.xml`（工作流 + 随包种子副本 `src/workflows/`）**：reuse 传参从 `boolean True` 改为 `string yes`——reuse 三态兼容参数（None/true/false，见 [multi-agent · agent_prompt 默认复用翻转](../architecture/multi-agent.md#agent_prompt-默认复用翻转2026-09-06用户提案commit-595fa2f)）的字符串形态对齐；宽松解析兼容旧值，**不改也能跑**。没手改过此工作流的 repo 升级后 `/update-assets apply` 走 `seed_newer` 自动更新。
2. **`src/assets/main.yml`（主 Agent 播种源）**：装配清单加 `- recent_file` 段——[recent-file 段式化第四版](../architecture/context-engine.md#修复八第四版段式化快照独立装配段-_seg_msgs_recent_file2026-09-07用户提案) 随包入库，其它 repo `/update-assets` 即拿到段式快照投影。

## 播种机制三类划分（发布答疑）

用户问「改过的工作流插件工具啥的是不是需要重新播种一下」——按资产类别三答：

| 类别 | 要不要播种 | 生效方式 |
|------|-----------|---------|
| **引擎核心**（session/agent/chat/commands/server/snapshots/multiagent/index.html） | ❌ 不归播种体系 | 其它机器 `pip install -U agt-agent` 后 `/restart` 即新版 |
| **播种资产**（工作流 XML / 声明 yml 等随包种子副本） | ⚠️ 变了 2 个（见上） | `/update-assets`（三方 hash 判定；手改过的工作流跳过保护，`--force` 才覆盖；没手改的走 `seed_newer` 自动更新） |
| **工具脚本 / 节点插件**（`tools_builtin`/`nodes_builtin`） | ❌ 不归播种管 | 直接从随包 assets 目录扫描（无本地副本），pip 升级即新版 |

**用户全局配置不在播种管辖**：`~/.agt/main.yml` 是用户全局配置（播种只管 workspace `.agent/main.yml`，且「用户改过的绝不自动覆盖」）。其它电脑若有自定义清单（如 `steps=reasoning`），**需手动在 steps 后加一行 `- recent_file`**，否则段式快照不投影。

## 本机收尾

`/restart` 一次后 0.26.0 全部生效：agent_prompt 默认复用、rewind 撞车检测（自下一轮开始积累 git_head 记录）、recent-file 段式投影（`/context` 里多出 `recent_file(改文件快照段)` 一行）。
