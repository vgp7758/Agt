## 缓存收益（本版核心价值）

```
之前：tail/钩子/hint 每步新增 1-3 条独立消息 → 序列形状每步漂移 → 缓存边界抖动
现在：全部 merge 到已有消息 content 末尾 → 前缀 byte-stable 打满
```

三区各司其职：**区1 头部**（system/rules/ltm）不因 tail 变化而变——字节稳定前缀；**区2 对话本体**（history/user/steps）唯一随轮演化、决定消息形状；**区3 尾部动态**（tail.* + asm 动作项 + 钩子旁注）统一 `<system-reminder>` 包裹 merge 到末条 content 末尾——末条本就处于未命中区，动态内容变化只影响自身、前面已缓存前缀完整保留。

## 发布细节

- **投影三区重构（本批核心，commit fc3db93）**：tail merge（2026-08-31，bafaf7e）再进一步——tail 从写死一块拆成六个可配子段（time/system/plan/spec/episodic/remote，`set_assembly_plan` 对旧 `tail` 段自动 `_expand_tail()` 展开，yml 不改不断；`_tail_block_msgs` 按子段收集、空段零噪声）；steps 之后的全部动态内容（tail.* + asm 动作项 + 钩子旁注）统一 `<system-reminder>` 包裹后 merge 到末条 content 末尾——消息序列形状完全由对话本体决定 → byte-stable 最大化。
- **load_remote_instances 迁移**：远程实例清单从 SYSTEM 头部（main.yml 的 `{func:load_remote_instances()}` 占位）迁移到 `tail.remote` 段（agent.py 挂 `_remote_provider`）——实例连接/断开变化只落在区3 末条，零缓存代价（此前在头部，变化全序列断）。
- **钩子注入 merge 化（同批，src/agent.py）**：before_turn hint merge 到当前轮 user 消息 content 末尾；before_tool / after_tool / before_answer 的 notes 按 hook 位置分组（`OrderedDict` 归组）渲染后 merge 到 `msgs[-1]` content 末尾；msgs 空 / 末条 assistant 兜底独立 user 消息（重做草稿场景，不污染草稿语义）。
- **hook_note 落盘 + 前端折叠（用户提问触发，commit acc06f1）**：`_run_hooks` 每项 inject 结果作为 hook_note 事件写入 events.jsonl——「钩子注入只有当轮 react 看得到」的观测缺口补上，事后审查与读档回放可见；前端实时折叠成记录提示 `⚡ [位置]钩子注入「name」· run=xxx（N字·点击展开）`（紫 #7c3aed），历史读档不渲染（UI 不堆砌历史噪声、磁盘保留完整真相）。
- **版本 bump**：run_python 脚本直接改 `src/__init__.py` 的 `__version__`（0.22.6 → 0.22.7）——0.22.4 确立的「脚本直改版本号」发版流程延续，干净一次过。
